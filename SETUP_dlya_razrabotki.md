## 1. Установить Unity 6.3 LTS + Android-модули ⬅️ ГЛАВНОЕ

### 1.1. Скачать Unity Hub

- Ссылка: <https://unity.com/download> → «Download for Windows».
- Установка обычная, «Далее». Нужны **права администратора** (UAC).

### 1.2. В Hub установить редактор

1. Открыть Unity Hub → **Installs** → **Install Editor**.
2. Вкладка **Archive** (или список LTS) → выбрать **Unity 6.3 LTS** (версия `6000.3.x`, последний патч).
   - Если 6.3 в списке нет — взять любую **6000.3.x** из архива: <https://unity.com/releases/editor/archive>.
   - ⚠️ Unity 2022.3 LTS ставить **не надо** — он снят с поддержки, а туториалы из интернета в основном для него; часть API будет отличаться.
   - ⚠️ **Unity 6.6 ставить не надо** — это Stable-поток, а не LTS: патчи только до выхода следующей линии, в нём переделывают 2D-физику (у нас весь персонаж на `Rigidbody2D`/`HingeJoint2D`) и есть известный баг с Android back-жестом после выхода из фона. Плюс проект, открытый в 6.6, уже не открыть в 6.3. Решение зафиксировано: **6.3 LTS**.
3. В окне выбора модулей **обязательно** отметить:

| Модуль | Зачем |
|---|---|
| ✅ **Android Build Support** | Сборка APK |
| ✅ **Android SDK & NDK Tools** (внутри Android Build Support) | Компиляция Android-части |
| ✅ **OpenJDK** (внутри Android Build Support) | Gradle-сборка, чтобы не зависеть от вашего JDK 25 |
| ✅ **Windows Build Support (IL2CPP)** | Быстрая проверка на ПК без телефона (экономит часы) |
| ⬜ Документация / WebGL / iOS / Linux | Не нужны, не ставить (экономия 10+ ГБ) |

4. Дождаться окончания (≈ 8–14 ГБ скачивания).

### 1.3. Активировать лицензию

1. Unity Hub → иконка профиля → **Sign in** (нужен аккаунт Unity; регистрация бесплатная).
2. **Preferences → Licenses → Add → Get a free personal license**.
3. Проверить, что в списке лицензий есть **Personal** и она активна.

> Без этого шага `Unity.exe -batchmode` завершится ошибкой лицензии, и я не смогу собирать APK автоматически. Войти в аккаунт за вас я не могу (нужны ваши учётные данные).

### 1.4. Сообщить мне точный путь

В Hub: **Installs → ⚙️ (рядом с версией) → Show in Explorer**. Скопировать путь к папке `Editor`.

Пришлите одной строкой, например:

```
C:\Program Files\Unity\Hub\Editor\6000.3.12f1\Editor\Unity.exe
```

Плюс подтверждение: «лицензия активирована, вход выполнен».

### 1.5. Проверка, которую я прогоню сам

```powershell
# 1. версия и валидность установки
& "<путь>\Unity.exe" -version -batchmode -quit

# 2. что модуль Android на месте
Test-Path "<путь>\Data\PlaybackEngines\AndroidPlayer\SDK\platform-tools\adb.exe"
Test-Path "<путь>\Data\PlaybackEngines\AndroidPlayer\NDK"

# 3. smoke-сборка пустого проекта (2–4 мин)
& "<путь>\Unity.exe" -batchmode -quit -nographics `
  -projectPath "<тестовая папка>" -executeMethod BuildScript.BuildAndroid `
  -logFile "<тестовая папка>\Logs\build.log"
```

Если эти три проверки проходят — риск «не собралось на телефоне» (RISK-02) закрыт в первый же день.

## 2. Перенести проект в нормальную папку (5 минут)

Сейчас проект лежит в `C:\Users\rafael\Desktop\stickman fight`. Для Unity это плохое место по двум причинам:

1. **Пробел в пути** — часть инструментов (Gradle, NDK, keytool) спотыкается на пробелах, приходится всё экранировать.
2. **Рабочий стол** — часто синхронизируется (OneDrive/бэкап), а Unity создаёт папку `Library` на 2–4 ГБ с тысячами файлов, которую синхронизация мучает и тормозит редактор.

**Рекомендую:** перенести в `C:\Dev\stickman-fight` (без пробелов, вне синхронизации).

```powershell
New-Item -ItemType Directory -Force C:\Dev | Out-Null
Move-Item "C:\Users\rafael\Desktop\stickman fight" "C:\Dev\stickman-fight"
```

> Если хотите оставить на рабочем столе — работать можно, я всё экранирую. Просто предупреждаю о риске.

## 3. Телефон для тестов (обязательно для приёмки)

Без реального устройства NFR-PERF-01 и половина тест-кейсов непроверяемы: эмулятор не показывает ни FPS, ни ощущения от тача.

- Любой телефон **Android 8+**, 2019 года или новее.
- Включить: **Настройки → О телефоне → 7 раз тап по «Номер сборки» → Для разработчиков → Отладка по USB**.
- При первом подключении на телефоне подтвердить «Разрешить отладку».

### 3.1. Проверка подключения

```powershell
$adb = "C:\Program Files\Unity\Hub\Editor\6000.3.29f1\Editor\Data\PlaybackEngines\AndroidPlayer\SDK\platform-tools\adb.exe"
& $adb devices
```

Нужна строка `<серийник>  device`. Если написано **`unauthorized`** — на экране телефона висит (или уже пропущено) окно «Разрешить отладку по USB?». Нужно:

1. Разблокировать телефон.
2. Нажать **«Разрешить»** (и поставить галочку «Всегда разрешать с этого компьютера»).
3. Если окно не появляется: отключить и снова подключить кабель, либо в «Для разработчиков» нажать **«Отменить авторизацию USB-отладки»** и подключиться заново.

### 3.2. Установка сборки на телефон

```powershell
$adb = "C:\Program Files\Unity\Hub\Editor\6000.3.29f1\Editor\Data\PlaybackEngines\AndroidPlayer\SDK\platform-tools\adb.exe"
$apk = "C:\Dev\stickman-fight\builds\StickmanFight_v0.1.0.1.apk"

& $adb install -r $apk          # -r = переустановка с сохранением данных
& $adb shell am start -n com.stickmanfight.game/com.unity3d.player.UnityPlayerGameActivity
& $adb logcat -s Unity          # логи игры в реальном времени (Ctrl+C — выход)
```

Полезное:

| Команда | Что делает |
|---|---|
| `adb shell screencap -p /sdcard/s.png && adb pull /sdcard/s.png` | скриншот экрана телефона |
| `adb shell dumpsys gfxinfo com.stickmanfight.game` | статистика отрисовки (для FPS-проверок) |
| `adb uninstall com.stickmanfight.game` | удалить игру |

**Если телефона нет:** вариант «через файл» — я собираю APK, вы перекидываете его на телефон (Telegram/кабель) и ставите вручную. Работает, но медленнее цикл правок (нет `adb logcat` — причины крашей придётся смотреть только глазами).

## 6. Как мы будем работать

1. **Git с первого дня.** Я инициализирую репозиторий, `.gitignore` (Unity-шаблон), `.gitattributes` (LFS), ветки `main`/`dev`. Коммит — минимум раз в день.
2. **Собираемый APK каждые 3–4 дня** (гейты G0…G7 из раздела 11 ТЗ). Игра никогда не бывает «в нерабочем состоянии» дольше одного спринта.
3. **Ваши 15 минут в день:** установить свежий APK и поиграть. Без этого я не увижу проблем с ощущениями (RISK-04) — код-то я проверю, а «неудобно» — нет.
4. **Формат обратной связи** — короткий, но конкретный:

```
[насколько сильно] что случилось. Шаги. Ожидал / получил.
Пример: [S2] Прыгаю у стены — застреваю в воздухе, падает только через 2 сек. Шаги: подойти к левой стене, зажать ▶ + прыжок.
```

5. **Новые идеи** — только в `BACKLOG.md`, в код не идут, пока не закрыт DoD (раздел 14 ТЗ). Иначе проект не доживёт до 30-го дня.
6. **Я не меняю стек посреди проекта.** Решение по движку фиксируется до G0.

7. Отчёт: что собралось, что нет, скриншот/лог, следующий шаг.

## 8. Если Unity поставить нельзя (fallback)

Решение принимается **до** G0. Если Unity не вариант — два рабочих пути:

### Вариант 1: Godot 4 (лёгкий, полностью CLI)

- Что нужно: `Godot_v4.x-stable_win64.exe` (~120 МБ, без установки), Export Templates (~700 МБ), **Android SDK** (cmdline-tools) + **JDK 17**.
- Плюсы: ставится за 20 минут, проект текстовый (сцены `.tscn`), сборка APK одной командой `--headless --export-release "Android"`.
- Минусы: ваша команда, скорее всего, не знает Godot; туториалов и готовых ragdoll-решений меньше.

### Вариант 2: Веб-прототип (запускается прямо сейчас)

- Что уже есть: Node.js, браузер, мои инструменты для запуска и скриншотов страницы.
- Плюсы: могу показать работающую физику **сегодня**, без установок; правки — мгновенно.
- Минусы: APK только через обёртку (Capacitor/TWA), и для этого всё равно нужен Android SDK; «нативное» ощущение хуже.

### Вариант 3 (рекомендую, если Unity ставится): **параллельно**

Пока Unity скачивается, я делаю в браузере одноразовый прототип физики — стойка, падение, удар, ragdoll. Он нужен не как продукт, а чтобы **до** написания Unity-кода проверить, что ощущения правильные (закрывает RISK-01 и RISK-04 на 3 недели раньше). После подтверждения переношу те же константы в Unity.

Скажите, если такое параллельное «черновое» железо вам не нужно — тогда просто жду Unity.
