# ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ)
## Проект: Physics Stickman Playground

**Тип проекта:** 2D Physics Sandbox / Fighting Game  
**Платформа:** Android  
**Срок разработки:** 30 календарных дней  
**Команда:** начинающие разработчики  
**Цель:** создать играбельный мобильный прототип, объединяющий механику боёв из Supreme Duelist Stickman и физическую песочницу в духе People Playground.

---

# 1. Концепция игры

Разработать 2D-игру с физикой ragdoll, в которой игрок может управлять человечком-стикменом, сражаться с другими персонажами, использовать оружие, взаимодействовать с предметами и экспериментировать с физикой игрового мира.

Основная идея — объединить два игровых направления:

- **Supreme Duelist Stickman:** динамичные сражения, простое управление, оружие, арены.
- **People Playground:** физические взаимодействия, ragdoll-анимации, предметы, столкновения и возможность экспериментировать с объектами.

Игрок должен не только сражаться, но и иметь возможность свободно взаимодействовать с игровым окружением.

# 2. Основные игровые режимы

### 2.1. Режим сражения (Battle Mode)

Основной режим игры.

Требования:
- Игрок управляет одним стикменом.
- Противник управляется компьютером.
- Персонажи имеют физическую ragdoll-модель.
- Возможность наносить удары и использовать оружие.
- Физические столкновения между персонажами.
- Система здоровья.
- Победа при устранении противника.

Минимум для первой версии:
- 1 игрок.
- 1 противник.
- 1 игровая арена.
- 3 вида оружия.

### 2.2. Режим песочницы (Sandbox Mode)

Режим свободного взаимодействия с объектами.

Требования:
- Возможность создавать или размещать предметы на карте.
- Возможность перемещать объекты.
- Возможность бросать предметы.
- Физическое взаимодействие между объектами.
- Возможность взаимодействовать с персонажами.
- Возможность экспериментировать с физикой.

Минимальный набор объектов:
- Ящик.
- Металлический блок.
- Мяч.
- Персонаж-стикмен.
- Несколько видов оружия.

# 3. Персонажи и физика

Персонажи должны иметь упрощённую ragdoll-физику.

Обязательные особенности:
- Физические конечности.
- Столкновения с окружающими объектами.
- Реакция на удары.
- Возможность падать и подниматься либо возвращаться в боевое положение.
- Получение урона при столкновениях и ударах.
- Возможность удерживать оружие.

Не требуется создавать сложную систему анимации. Приоритет — физическое поведение персонажа.

# 4. Оружие

В первой версии необходимо реализовать три типа оружия:

1. **Меч** — оружие ближнего боя.
2. **Молот** — наносит урон при физическом столкновении.
3. **Пистолет** — стреляет снарядами.

Дополнительные требования:
- Возможность подбирать оружие.
- Возможность отпускать оружие.
- Возможность наносить урон противнику.
- Физические столкновения оружия с объектами.

# 5. Игровое управление

Управление должно быть адаптировано под сенсорный экран Android.

Минимальные элементы управления:
- Левая и правая кнопки движения.
- Кнопка атаки.
- Кнопка прыжка.
- Кнопка взаимодействия.
- Кнопка выбора или смены оружия.

В режиме песочницы:
- Нажатие на объект — выбор.
- Перетаскивание — перемещение.
- Кнопка создания объекта — появление нового предмета.

Интерфейс должен быть простым и понятным.

# 6. Игровые локации

Для первой версии достаточно двух локаций:

**Арена:**
- Плоская игровая поверхность.
- Ограниченные границы карты.
- Возможность сражаться с противником.

**Песочница:**
- Пространство для свободного размещения объектов.
- Отсутствие обязательных противников.
- Возможность создавать физические взаимодействия.

# 7. Техническая реализация

Рекомендуемый движок: Unity 2D.

Почему:
- Поддерживает Android.
- Имеет встроенную физику 2D.
- Позволяет использовать готовые ассеты и prefab-объекты.
- Есть визуальное программирование Unity Visual Scripting.
- Можно найти готовые решения для ragdoll-физики.

Разработку необходимо вести с использованием готовых бесплатных или доступных ассетов, шаблонов и компонентов, если это ускоряет работу.

Необходимо избегать написания сложных систем с нуля.

**Важно:** использование готовых компонентов допускается, но команда должна понимать, как они работают и как объединить их в одну игру.

# 8. Графика и интерфейс

Визуальный стиль:
- Минималистичный 2D.
- Стикмены.
- Простые геометрические объекты.
- Контрастные цвета.
- Минимум сложных визуальных эффектов.

Не требуется создавать профессиональную графику.

Главная цель — рабочая физика и игровой процесс, а не красивая картинка.

# 10. Критерии готовности проекта

Проект считается выполненным, если:

- [ ] Игра запускается на Android.
- [ ] Есть главное меню.
- [ ] Работает управление персонажем.
- [ ] Персонаж взаимодействует с физическими объектами.
- [ ] Работает ragdoll-физика.
- [ ] Есть хотя бы один игровой противник.
- [ ] Реализованы три вида оружия.
- [ ] Работает система здоровья.
- [ ] Реализован режим сражения.
- [ ] Реализован базовый режим песочницы.
- [ ] Можно создавать и перемещать объекты.
- [ ] Нет критических ошибок, препятствующих игре.

# 11. Ограничения проекта

Учитывая срок разработки и уровень подготовки команды, запрещается расширять проект за счёт следующих функций до завершения основной версии:

- Онлайн-мультиплеер.
- Сложный искусственный интеллект.
- Большое количество персонажей.
- Продвинутая система крови и повреждений.
- Огромные игровые карты.
- Сложная система инвентаря.
- Полноценная система сохранений.
- Сложные анимации и кинематографические эффекты.

Любые дополнительные функции могут добавляться только после выполнения обязательных требований.

# 12. Итоговый результат

К концу 30-го дня команда должна предоставить:

1. Готовую Android-сборку APK.
2. Исходный проект Unity.
3. Два работающих игровых режима.
4. Реализованную физику персонажей и объектов.
5. Демонстрацию игрового процесса.

**Главный приоритет проекта: РАБОЧИЙ ПРОТОТИП, А НЕ ИДЕАЛЬНАЯ ИГРА.**

Лучше сделать небольшую, но полностью работающую игру, чем за месяц создать десятки недоделанных механик.
